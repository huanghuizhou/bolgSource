## 一、OpenClaw 简介

OpenClaw是适用于任何操作系统的 AI 智能体。它通过技能（Skill）系统扩展能力，可以帮你完成代码编写、问题排查、文档整理、定时任务等各种工作。

---

## 二、安装初始化流程

小龙虾安装流程 网上资源比较多，这里不过多介绍。

### 2.1 安装 OpenClaw

```bash
# 使用 Homebrew 安装（macOS）
brew install openclaw

# 或手动安装
npm install -g openclaw
```

初始化后会生成以下核心文件：

| 文件 | 作用 |
|------|------|
| `SOUL.md` | AI 助手的人格定义（语气、风格等） |
| `USER.md` | 用户画像（你的名字、时区等） |
| `IDENTITY.md` | AI 助手的身份信息 |
| `MEMORY.md` | 长期记忆存储 |
| `TOOLS.md` | 本地工具配置 |
| `HEARTBEAT.md` | 心跳检测配置 |

### 2.2 启动 Gateway 服务

```bash
# 启动 OpenClaw 后台服务
openclaw gateway start

# 查看状态
openclaw gateway status
```

### 2.3 消息通道配置

OpenClaw 支持多种消息通道，如飞书、Telegram、Discord 等：

```bash
# 配置飞书通道
openclaw channel add feishu

# 按照提示配置 webhook 和密钥
```

## 三、Skill 简介

### 3.1 什么是 Skill？

Skill 是 OpenClaw 的能力扩展单元，每个 Skill 封装了特定领域的功能。比如：
- 查天气的 `weather` skill
- 查日志的 `zan-log-query` skill
- 代码生成的 `coding-agent` skill

### 3.2 安装 Skill

```bash
# 从 clawhub 搜索技能
clawhub search weather

# 安装技能
clawhub install weather

# 查看已安装技能
clawhub list
```

### 3.3 常用 Skill 推荐

#### 常用skill

| Skill | 功能 | 使用场景 |
|-------|------|----------|
| `weather` | 天气查询 | 定时播报天气 |
| `self-improving` | 小龙虾基建 | 记录经验教训、错误和纠正措施，以实现持续改进 |
| `github` | GitHub 操作 | PR 查看、Issue 管理 |
| `tavily-search` | 搜索 | 联网搜索资料 |
| `local-knowledge-mcp` | 本地知识库 | 代码语义搜索 |
| `feishu-doc` | 飞书文档 | 读写飞书文档 |

**安装方式：**
```bash
clawhub install weather coding-agent github tavily-search
```

### 3.4 Skill 使用示例

每个 Skill 都有对应的 `SKILL.md` 文档，使用前建议先阅读：

```bash
# 查看 skill 文档位置
ls ~/.openclaw/workspace/skills/<skill-name>/SKILL.md
```

## 五、问答助手 Agent 实践

### 5.1 背景

作为一名后端 Java 开发工程师，日常工作中经常面临各种咨询：

| 咨询来源 | 典型问题 |
|---------|---------|
| **产品经理** | "销售明细查询支持发货时间维度能不能做？" |
| **技术支持** | "存货核算支持哪些成本计算方式？" |
| **上下游开发** | "我的退款消息延迟，对你下游影响大吗？" |
| **新人 onboarding** | "结算单状态流转规则是什么？" |

现有的知识库问答助手是比较成熟的，但是仅用业务知识库检索存在缺陷：

- ❌ 知识库不懂代码实现细节
- ❌ 无法回答"能不能做"的技术可行性问题
- ❌ 无法解释"为什么这样实现"



目前大模型对于代码的分析能力是比较到位的，如果能识别到对应的源码项目，结合代码进行答疑，能解决上面大部分问题。

**解决思路：**

如果先通过知识库召回业务知识，再结合 AI 分析本地代码，理论上能回答绝大部分咨询问题。

这个 Agent 可以看作是**研发的替身** —— 当你请假时，它能承接你的大部分咨询工作。

### 5.2 实现流程

### Step 1：创建独立的财务咨询 Agent

由于 main 主 Agent 加载了太多 skills（weather、github、zan-log-query...），导致：
- skill识别混乱
- Token 消耗过多
- 不够专业聚焦

**解决方案：** 创建一个新的财务咨询 Agent，只加载必要的 skill。

```bash
# 创建工作空间
mkdir -p ~/.openclaw/workspace-finance-knowledge-qa

# 创建 AGENTS.md
cat > ~/.openclaw/workspace-finance-knowledge-qa/AGENTS.md << 'EOF'
# finance-qa Agent 配置

- **Agent ID:** finance-qa
- **Name:** 小财
- **Description:** 财务域技术咨询助手，专注回答结算、核算、销售、绩效等业务问题

### 核心 Skill
- finance-rag-builder    # 知识库构建
- finance-qa-assistant   # 问答答疑
- feishu-doc             # 飞书文档读取
- feishu-wiki            # 飞书 Wiki 读取
- local-knowledge-mcp    # 本地代码语义搜索

### 工作目录
- knowledge/finance-rag/ - 生成的知识库
- knowledge/prd/         - PRD 源文件
- knowledge/code/        - 代码仓库
EOF
```

注册到 OpenClaw：

```bash
openclaw agent add finance-qa \
  --workspace ~/.openclaw/workspace-finance-knowledge-qa \
  --skills finance-rag-builder,finance-qa-assistant,feishu-doc,feishu-wiki,local-knowledge-mcp
```

````
# Developer QA Skill

## 功能概述

本 Skill 用于解答财务域技术咨询问题，通过**Aily 知识库查询** + **本地代码分析**双引擎，提供准确的业务和技术答案。

## 工作流程

```
用户提问
    ↓
调用 Aily 知识库查询 (feishu_skill_caller.py)
    ↓
读取 code/index.md 分析涉及项目
    ↓
读取相关项目源码
    ↓
综合分析生成答案
    ↓
返回精简结论（附代码依据）
```

## 使用场景

| 场景类型 | 示例问题 |
|---------|---------|
| 成本核算 | 移动加权平均价不同供应商是否分别计算？ |
| 报表统计 | 营业概况中营业目标完成度计算口径？ |
| 消息延迟 | 换货核算消息延迟对财务域的影响？ |
| 业务逻辑 | 结算单状态机流转规则？ |
| 数据一致性 | 销售明细与毛利表差异原因？ |

## 执行步骤

### Step 1: 调用 Aily 知识库

```bash
cd ~/.openclaw/workspace-finance-knowledge-qa/developer-qa/scripts
python feishu_skill_caller.py \
  --message "用户问题"
```

**输出：** 知识库返回的相关业务知识

### Step 2: 读取代码索引

```bash
read ~/.openclaw/workspace-finance-knowledge-qa/code/index.md
```

**目的：** 根据问题关键词，定位涉及的代码项目

### Step 3: 分析涉及项目

根据 index.md 中的「快速导航」和「应用间依赖关系」，确定需要分析的代码项目：

| 问题类型 | 主要应用 | 关键实体/服务 |
|---------|---------|--------------|
| 销售核算 | retail-finance-sales | GoodsSalesRecordV2Entity, ProfitDetailEntity |


### Step 4: 读取并分析源码

**定位文件：**
```bash
# 按实体查找
find ~/.openclaw/workspace-finance-knowledge-qa/code -name "*Entity.java" | xargs grep -l "关键词"

# 按服务查找
find ~/.openclaw/workspace-finance-knowledge-qa/code -name "*Service.java" | xargs grep -l "关键词"

# 按方法查找
find ~/.openclaw/workspace-finance-knowledge-qa/code -name "*.java" | xargs grep -l "方法名"
```

**读取关键代码：**
```bash
read ~/.openclaw/workspace-finance-knowledge-qa/code/{应用}/{模块}/.../{文件}.java
```

### Step 5: 生成答案

**答案结构：**
```markdown
## 结论
一句话核心答案

## 详细说明
1. 业务逻辑说明
2. 代码实现说明

## 代码依据（如有）
```java
// 关键代码片段
```

## 来源
- [飞书知识库]
- [代码] `ClassName.java`
```

**回答原则：**
1. **精简为主** - 先说结论，再展开
2. **代码说话** - 有代码依据时贴代码，无代码依据可不贴
3. **避免啰嗦** - 不要"好的，我来帮你分析"等废话
4. **结构清晰** - 使用表格、列表、代码块提升可读性

.
.
.
.
````

## 六、基于 Kimi 实现代码开发流程

### 6.1 背景

小龙虾底层使用 Kimi 2.5 大模型，而 Kimi 提供了 Code 客户端支持 CLI 操作。同时cursor有比较成熟的 **OpenSpec 开发范式**。

**思考：** 能不能把「需求澄清 → 方案设计 → 代码生成 → Code Review」整个流程串起来，实现端到端的自动化开发？

### 6.2 dev-workflow-kimi Skill 介绍

**设计目标：**
- 需求脑暴澄清 → OpenSpec 规范生成 → Kimi CLI 代码生成 → Code Review → 提交归档

**工作流程图：**

## 七、使用心得

1. **按需加载**：过多的skill会让ai识别混乱，且消耗过多token。必要时可以抽象出一个新的agent出来，只加载必要的skill

2. **明确指令**：尽量清晰地描述你的需求

3. **分步执行**：复杂任务拆分为多个小步骤

4. **善用记忆**：让 OpenClaw 记住你的偏好和常用配置

5. **及时反馈**：回答不符合预期时及时纠正
